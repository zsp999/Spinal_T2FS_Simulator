**Model Usage Instructions**

# Prerequisites
To use our model for inference or fine-tuning, please ensure:

1. Data Compatibility: For optimal performance, we recommend structuring your data according to the format demonstrated in ./test_sample/preprocessed_data
2. Input Format: The model expects multi-modal MRI sequences converted to 3-channel pseudo-color images as input

# Data Preparation
We provide two pathways to accommodate different research needs:

***Option 1***: Using Our Preprocessed Format (Recommended for Quick Start)
To facilitate immediate testing and replication, we have included example preprocessed data in ./test_sample/preprocessed_data/. These 3-channel pseudo-color images demonstrate the expected input format generated by stacking multi-modal MRI sequences. The corresponding output results for the three provided test cases can be found in the ./test_sample/test_results folder.

***Option 2***: Adapting to Your Custom Data
For researchers interested in applying our framework to their own datasets, we offer flexible adaptation approaches:
# A. Following Our Processing Pipeline
If your data structure is compatible, you can:
1. Data Preprocessing: From Medical Images to Multi-slice Raw Data
In accordance with the methodology described in the article, medical imaging files (e.g., in DICOM format) were preprocessed to extract multi-slice image data for each contrast channel, hereafter referred to as the raw-data (.png).
2. Channel-wise Concatenation: Constructing Three-channel Pseudo-color Images
Following a predefined contrast order (T1 → T2 → optional T2FS), images were concatenated along the channel dimension to form three-channel pseudo-color inputs. Specifically:
1) If T2FS images were available, the channel order was T1–T2–T2FS.
2) If T2FS images were unavailable, a zero matrix (placeholder) was used in the third channel. 
The resulting concatenated data are termed preprocessed_data (.png).
# B. Customizing for Your Specific Needs
Our model architecture and training framework are designed for adaptability. If your data format differs or you have specialized requirements:
1. Our pre-trained model can serve as an initialization point
2. You can fine-tune the model on your specific dataset
3. Modify the network input layers or architecture to better suit your data structure.

Flexibility Note: We have designed our codebase to be modular and adaptable. Researchers can modify the preprocessing steps and model inputs to suit their specific data characteristics while leveraging the core architectural innovations of our approach.
